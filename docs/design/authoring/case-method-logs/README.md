# Case Method Logs: Purpose And Index

> Current version: v0.1 DRAFT
> Last updated: 2026-11-13
> Status: Draft. Founder-directed practice, 2026-11-13.
> Canonical path: docs/design/authoring/case-method-logs/README.md

## Why these logs exist

There is no single universal story-writing method, and this folder does not try to write one. Each time a story is written, the method actually used is captured in its own log. Over several cases the logs are compared to find out which practices repeatedly produce what the founder is after, in his words: "incredible mind blowing stories, titillating puzzles, and addicting mysteries".

## The standing test

Founder, 2026-11-13: the methods, processes, models, concepts and algorithms used to write stories "should ensure that every story feels fresh and new and never like AI slop". Every log is written with that test in view. A log is not only a diary of steps; it records what was done to make this case unlike the ones before it and unlike generic machine writing, and later whether players felt that.

Each log therefore carries:

- **A freshness record.** What is new in this case compared with every earlier log: setting, era, social world, kind of impossible thing, structure, tone. If nothing is new on a dimension, say so.
- **The checks against generic writing that were actually run**, with what they caught.
- **After play: evidence.** Whether players described the case as surprising or as familiar, in their words where consent allows.

Dimensions that would spoil a case (the kind of trick, the culprit's role, the shape of the reveal) are compared across cases in a separate file marked as spoilers, so repetition can be caught without spoiling anyone. That file does not exist until the first solution does.

## Rules for a log

- **One log per case**, numbered in order, named for the premise and never for the solution.
- **Written as the work happens**, not reconstructed afterwards.
- **"Done" and "planned" stay separate.** A step counts as done only after it was used. Each done step records what was learned, including when it did not work.
- **Record the choices and who made them**, including when the founder chose against the author's recommendation.
- **No solution material.** A log must be safe to read for someone who intends to play the case.
- **Close each log with outcomes** once the case has been played: what players said and did, and which steps the author would keep, change or drop.

## Patterns across cases

Empty until at least two cases have been played. A practice is listed here only when it has appeared in more than one log together with evidence from play. One case is an anecdote.
