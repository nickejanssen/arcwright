# Session 1 Playthrough Versions (1a To 1e)

> Status: **proposed, not approved.** Task AW-346 (issue #429). Written 2026-11-20 from the founder interview recorded word for word on issue #429. Nothing here is a recorded decision until the founder approves this page; the answers below are what he said, and "meaning as understood" is the interviewer's reading.

## The short version

Five playthrough versions of Nightcap, each built for a different kind of player. Each is one setup of the game's rules file (the arc file): which mini-games run, how many, and how much racing, story or explaining surrounds them. All four share the same engine, the same screens and one common control mini-game, so the survey can compare them.

| Version | Built for | Main idea | New mini-game mechanics needed | Sheet |
| --- | --- | --- | --- | --- |
| **1a Agency race** (core) | Competitive players, the maximize-fun version | A dysfunctional detective agency racing to name the culprit first. Trivia mixed with case questions, building to a final race that runs straight into Last Call | Battle of Wits, Search and Find | [1a](1a-agency-race.md) |
| **1b Newcomers** | Friends who rarely play games | Fewest things to learn, more host explanation, no racing | Search and Find, Battle of Wits (easy questions) | [1b](1b-newcomers.md) |
| **1c Story and intrigue** | Players who care most about the characters and secrets | Few mini-games, more story weight, one private solo game | Search and Find, Lock Picking | [1c](1c-story-and-intrigue.md) |
| **1d Deduction and puzzles** | Players who like working it out | Mini-games framed as evidence work, logic questions, a lock to pick | Search and Find, Lock Picking, Battle of Wits (logic questions) | [1d](1d-deduction-and-puzzles.md) |
| **1e Variety** (Direction 1) | Players who like a mixed bag of games | A different investigator skill each round: Observation, Deduction, Interrogation, plus Lock Picking (Tradecraft) as an anytime game. No repeat, no final race | Search and Find, Battle of Wits, a bluffing game, Lock Picking | [1e](1e-variety.md) |

The control game is not a version. It is one mini-game (Search and Find, provisionally) that appears inside every version, so ratings can be compared. The candidate list and which version uses which game are in [minigame-slotting.md](minigame-slotting.md).

## How the versions differ at a glance

| | 1a Agency race | 1b Newcomers | 1c Story and intrigue | 1d Deduction and puzzles | 1e Variety |
| --- | --- | --- | --- | --- | --- |
| Main pressure | The clock and rivals | None | The story | The puzzle | Different skills |
| Mini-games in three rounds | 5, one kind repeated | 2 | 1 group, 1 solo | 3 | 3, a different kind each |
| Final race | Yes, into Last Call | No | No | No | No |
| Scoreboard weight | Loud | Light | Quiet | Light | Medium |
| Host explanation | Standard | Extra, plain words | Standard, more narration | Standard | Standard |
| Repeats a mechanic | Yes | No | No | No | No |
| Mechanics needed | Battle of Wits, Search and Find | Search and Find, Battle of Wits | Search and Find, Lock Picking | Search and Find, Lock Picking, Battle of Wits | Search and Find, Battle of Wits, bluffing game, Lock Picking |

The lettering is proposed: a and b are the versions the two-group plan plays first. D-144 called the agency race's final race "variant 1b"; making the agency race the core version (below) supersedes that label, so the orchestrator should amend D-144's wording if this page is approved.

The founder chose Newcomers over Social bluffers as the fourth version, and then asked for his original Direction 1 as a fifth version (answer 12), so the bluffing game now lives in 1e only. Social bluffers as a whole version waits until after December.

## Words used on these pages

| Word | Meaning |
| --- | --- |
| Version | One setup of the arc file, built for one kind of player (1a to 1e) |
| Playthrough | One group playing one version of one case from join to recap |
| Round | One beat of the story; the number of rounds is a setting, not a rule (D-145) |
| Mini-game | A short game inside a round. A **mechanic** is its rules; a skin only changes its look |
| Control game | The one mini-game every version plays with identical rules, so ratings can be compared |
| Cohort | A kind of player (competitive, newcomer, story lover, puzzle lover) |
| Group | The 2 to 4 people in one sitting |
| Anytime game | A mini-game that can occur at any time in a session, like Lock Picking when a player finds a locked box, as opposed to a game at a fixed point such as the slot after a round (founder, 20 November 2026). The sheets call a solo or pair anytime game a side game |

## Shared design

**Control game.** Search and Find (provisional) is played in every version with the same rules, scene and rating, on both cases. If a group's rating of it differs a lot between versions or cases, that difference is about the group or the case, not the version. If the founder changes the control, only this paragraph and the version arc setups change.

**Cohort games.** Each version adds its own: Battle of Wits for 1a, 1b and (logic only) 1d; Lock Picking for 1c and 1d. Where a cohort game is a new skin of an existing mechanic (D-143), it comes before a new mechanic.

**How a version picks its mini-games (verified by reading `engine/arc/models.py` and D-147).** A beat has a number of `mini_game` slots (zero is allowed). `mini_game_pick: listed` runs the Nth listed game in the Nth slot; `fitting` treats the list as a pool, filtered by the player count each game declares and by no-repeat, first one left. So 1a uses `listed` (repeating allowed) and 1b to 1d use `fitting` (no-repeat). The engine's no-repeat filter counts a mechanic once it has started in the session; the founder's answer 9 means a solo run must not count, which is a small addition to AW-345 (not yet built).

**Last Call stays the same in every version.** Each player privately locks a theory (spec 0094, AW-326). The winner is decided by the theory, never by a race or by speed (D-138, GDD).

## Run order with two groups

With the second case written (answer 4) and two groups (answer 7), the proposed order is counterbalanced so that case quality and order of play do not pass for version differences:

| Group | Case 1 | Case 2 |
| --- | --- | --- |
| Group 1 (competitive friends) | 1a Agency race | 1b Newcomers |
| Group 2 (friends who rarely play games) | 1b Newcomers | 1a Agency race |
| Group 3, if found (story lovers) | 1c Story and intrigue | 1d Deduction and puzzles |
| Group 4, if found (puzzle lovers) | 1d Deduction and puzzles | 1c Story and intrigue |
| Group 5, if found (variety lovers) | 1e Variety | 1a Agency race |

Each group plays its own cohort's version first, then a different one on the fresh case. That tests the founder's idea directly: does each kind of player prefer the version built for them? Recruiting uses a short screener about what people enjoy at game nights, asked by the founder before inviting.

**Candid limit (inferred).** Two groups of 2 to 4 give quotes and strong signals, not statistics. A group's second playthrough is also easier because they have learned the rules; the counterbalance cancels this only across groups. Treat results as lessons, not measurements.

## Survey: how the versions are told apart

Every player answers, after each playthrough:

| Question | Why |
| --- | --- |
| Fun, 1 to 5; felt like a detective, 1 to 5; play again, yes, maybe or no; optional comment | The approved core (spec 0095 decision 7, D-139). The pass bar on the status page |
| After each mini-game: a rating (loved, fine, skip) and "play this one again?" (yes or no), two taps | Compares mini-games across versions and against the control |
| One version question, different in each version (see the sheets) | Tests what that version is for |
| Did you need to ask the host a question during play? (host also counts) | Newcomer signal, collected in every version |
| About the case: 1 to 5, "I enjoyed this case" | Separates case quality from version quality |
| At the end of a group's second playthrough: which of the two did you prefer, and why? | Direct comparison |

The play record (D-115) tags every answer with the version name, the case and the group, so versions can be compared from saved data. The extra questions extend the approved survey (spec 0095 decision 7). That is a change to an approved decision, so it needs the founder's approval. The zero-build fallback is a printed card the founder reads out after each playthrough.
